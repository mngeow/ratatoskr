Ratatoskr documentation

One page that links to every document in the repository. Pick a decision record, a testing guide, a contract, or search for anything.

HTML documents open straight from this page. Markdown files are plain text: a browser may show them raw or offer to download them, so each has a Preview button that shows the text here, escaped, with no rendering and no server. Nothing on this page is fetched; it works from a local checkout.

Status words come from the documents themselves. A document is not evidence that something works unless it says so, and the team has not run most of what is described. Working papers and older reports are kept so nothing is hidden, and are labelled as history.

Decision records 8

ADR-0001 to ADR-0008. Each is a self-contained HTML page with its status near the top.

  • ADR-0001: MCP agent messagingHTML

    Why agents send through an MCP tool and receive through a gated paste, and how that works in the code. Architecture decisions live in docs/adr/; the README explains the convention

    Accepted

    docs/adr/0001-mcp-agent-messaging/index.html

  • ADR-0002: Cross-machine messagingHTML

    One rtk binary with gateway and runtime startup commands, a central gateway on the tailnet or, by opt-in, a LAN, with pairing, separately deployable runtimes, full message storage and immediate failure when a host is unreachable, plus earlier options as history, drawbacks and open questions

    Accepted for implementation 2026-11-05, Direct LAN added 2026-11-06; the user reports successful testing by hand, 2026-11-06, with setup and failure coverage unconfirmed; no automated test has run

    docs/adr/0002-cross-machine-messaging/index.html

  • ADR-0003: Per-host daemonHTML

    A daemon on each machine owns agents and workers, and the TUI becomes an attachable window. Records the user's decisions: workers within their parent's permissions, no nested spawning, workers stopped with their owner, a worker count limit, rtk daemon and rtk attach. Remote dispatch is deferred and worktrees undecided

    Accepted 2026-11-06; the daemon transition is built, without worker features; the user reports that it works in their testing on 2026-11-06, with one open bug about text appearing in prompt boxes

    docs/adr/0003-per-host-daemon/index.html

  • ADR-0004: Network tabHTML

    An additional tab in the attached window that lists hosts and sessions and enters a remote session as agent-net does (gateway for discovery and the entry question, direct SSH for the terminal), with interactive mockups and the trust boundary

    Proposed 2026-11-06; implemented in the working tree 2026-11-07 but never run; open choices are proposals

    docs/adr/0004-network-tab/index.html

  • ADR-0005: Host Agent Cards and the Graph tabHTML

    One public, unauthenticated A2A-style Agent Card per host daemon, edited only on that host (optionally from an LLM draft), polled by the gateway on a preset schedule, stored with the graph in the gateway SQLite database (new migration) and drawn as a graph of hosts in a third Graph tab. Corrects the discovery path to /.well-known/agent-card.json; a card is not an A2A implementation, the gateway database needs a migration, and the heartbeat stays the connection authority

    Proposed 2026-11-07, revised with the user's decisions the same day; first version committed 2026-11-08, never run. Corrected 2026-11-08 by the user: listener on by default, card.yaml instead of publish commands, model generation built; those corrections are in the working tree, never run, not committed

    docs/adr/0005-host-agent-cards-and-graph/index.html

  • ADR-0006: A2A routing and authenticated identityHTML

    The A2A part only: one endpoint per participant (a managed session, or an externally managed service that enrols, registers and speaks A2A), how the sender is proven, and tasks with a clarification, a result and polled retrieval, with animated diagrams and the technical compliance obligations. OpenRig integration and discovery are separate records (0007, 0008)

    Proposed 2026-11-07; first delivery reduced 2026-11-08; first delivery written on the branch feat/a2a-participants, compile-checked, never run

    docs/adr/0006-a2a-routing-and-identity/index.html

  • ADR-0007: OpenRig operator integrationHTML

    Only the main OpenRig operator gets a network identity, as an externally managed participant behind a small bridge that speaks the ADR-0006 contract; OpenRig keeps its teams, lifecycle, terminals and queues, and an A2A message is never a queue item

    Proposed 2026-11-08; proposal only, nothing built or run

    docs/adr/0007-openrig-operator-integration/index.html

  • ADR-0008: Agent discovery toolHTML

    One tool, ratatoskrdiscover, returns a compact list of host cards, descriptions, capabilities, hosts and exact contactable sessions; the model chooses, and the gateway does no search or ranking

    Proposed 2026-11-08; proposal only, nothing built or run

    docs/adr/0008-agent-discovery-tool/index.html
