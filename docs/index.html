Decision records 9

ADR-0001 to ADR-0009. Each is a self-contained HTML page with its status near the top. ADR-0006 is deferred.

  • ADR-0001: MCP agent messagingHTML

    Why agents send through an MCP tool and receive through a gated paste, and how that works in the code. Architecture decisions live in docs/adr/; the README explains the convention

    Accepted

    docs/adr/0001-mcp-agent-messaging/index.html

  • ADR-0002: Cross-machine messagingHTML

    One rtk binary with gateway and runtime startup commands, a central gateway on the tailnet or, by opt-in, a LAN, with pairing, separately deployable runtimes, full message storage and immediate failure when a host is unreachable, plus earlier options as history, drawbacks and open questions

    Accepted for implementation 2026-11-05, Direct LAN added 2026-11-06; the user reports successful testing by hand, 2026-11-06, with setup and failure coverage unconfirmed; no automated test has run

    docs/adr/0002-cross-machine-messaging/index.html

  • ADR-0003: Per-host daemonHTML

    A daemon on each machine owns agents and workers, and the TUI becomes an attachable window. Records the user's decisions: workers within their parent's permissions, no nested spawning, workers stopped with their owner, a worker count limit, rtk daemon and rtk attach. Remote dispatch is deferred and worktrees undecided

    Accepted 2026-11-06; the daemon transition is built, without worker features; the user reports that it works in their testing on 2026-11-06, with one open bug about text appearing in prompt boxes

    docs/adr/0003-per-host-daemon/index.html

  • ADR-0004: Network tabHTML

    An additional tab in the attached window that lists hosts and sessions and enters a remote session as agent-net does (gateway for discovery and the entry question, direct SSH for the terminal), with interactive mockups and the trust boundary

    Proposed 2026-11-06; implemented in the working tree 2026-11-07 but never run; open choices are proposals

    docs/adr/0004-network-tab/index.html

  • ADR-0005: Host Agent Cards and the Graph tabHTML

    One public, unauthenticated A2A-style Agent Card per host daemon, edited only on that host (optionally from an LLM draft), polled by the gateway on a preset schedule, stored with the graph in the gateway SQLite database (new migration) and drawn as a graph of hosts in a third Graph tab. Corrects the discovery path to /.well-known/agent-card.json; a card is not an A2A implementation, the gateway database needs a migration, and the heartbeat stays the connection authority

    Proposed 2026-11-07, revised with the user's decisions the same day; first version committed 2026-11-08, never run. Corrected 2026-11-08 by the user: listener on by default, card.yaml instead of publish commands, model generation built; those corrections are in the working tree, never run, not committed

    docs/adr/0005-host-agent-cards-and-graph/index.html

  • ADR-0006: A2A routing and authenticated identityHTML

    Historical: the A2A part only: one endpoint per participant (a managed session, or an externally managed service that enrols, registers and speaks A2A), how the sender is proven, and tasks with a clarification, a result and polled retrieval, with animated diagrams and the technical compliance obligations. OpenRig integration and discovery are separate records (0008, 0009)

    Deferred 2026-11-08 (A2A does not fit the current need; see the deferral record); kept as a historical proposal; nothing on main is built or run

    docs/adr/0006-a2a-routing-and-identity/index.html

  • ADR-0007: Adapter integration contractHTML

    A language-neutral participant contract that lets outside harnesses and orchestrators (OpenRig, Pi, custom) join through adapters written in any language: roles and trust, identity and many sessions per participant, the send, receive and status flows, versioning, security, the chosen HTTP+JSON participant API (all seven recommendations approved; participant API implementation contract) with the other six options kept and their drawbacks, four inbound-delivery mechanisms, and the difference between conversation and delegated work. A2A is deferred and not assumed

    Proposed 2026-11-08; the user approved all seven recommendations the same day (HTTP+JSON participant API, long-poll inbox, pairing code, LAN and tailnet only); implementation started on branch feat/adapter-integration, never run

    docs/adr/0007-adapter-integration-contract/index.html

  • ADR-0008: OpenRig operator integrationHTML

    Only the main OpenRig operator gets a network identity, through a Go sidecar-plus-client bridge (participant-API adapter, ADR-0007) supervised by the OS service manager; inbound is rig send and OpenRig sees an unknown sender; no sender allow-list in v1; OpenRig keeps its seat launch, MCP and hook configuration, terminals and queues. Skill-plus-command versus MCP for outbound is the open choice

    Proposed 2026-11-08, revised for the A2A deferral, source-grounded against OpenRig 0.7.7, and updated 2026-11-09 with the user's choices; outbound mechanism still open; nothing built or run

    docs/adr/0008-openrig-operator-integration/index.html

  • ADR-0009: Agent discovery toolHTML

    One tool, ratatoskrdiscover, returns a compact list of host cards, descriptions, capabilities, hosts and exact contactable sessions, in TOON for the model only (JSON everywhere else); the model chooses, and the gateway does no search or ranking. Also a proposed HTMX gateway dashboard (Cytoscape.js graph, Agent Card panel, cream-palette mock-ups) that is open to anyone with the link, with no authentication and no TLS in v1 (plain HTTP), read-only, showing exact session ids and all card details, on a default 0.0.0.0 bind; every gateway service defaults to that bind, the dashboard shares port 7777, and the wildcard and public-address refusals are removed, so firewalling is the exposure boundary; the shared 7777 is plain HTTP by default (host credentials and messages in cleartext) with HTTPS plus fingerprint pairing as an opt-in, the participant API on 7790 stays HTTPS by default, and the gateway's --allow-lan and --insecure-http flags are retired (decided, not built)

    Proposed 2026-11-08, revised the same day to be independent of A2A, and revised three times on 2026-11-11 with the owner's TOON, dashboard, open-access, bind, Cytoscape.js, palette, no-TLS, visibility and read-only decisions; proposal only, nothing built or run

    docs/adr/0009-agent-discovery-tool/index.html
