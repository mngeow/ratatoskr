# A2A participants: implementation contract (first delivery)

Owner: `design.architect`. Branch: `feat/a2a-participants`. Authority: the user's go-ahead (relayed 2026-11-08: "Go ahead and begin implementation, be sure to checkout a new feature branch before beginning") and the six final choices in [ADR-0006 section 1b](../adr/0006-a2a-routing-and-identity/index.html#decided). **Nothing here has been built or run.** GR-3 applies: write and type-check, never execute; no commit or push without the user.

This is the contract the seniors build against. It fixes the decisions that must not be re-argued and leaves the low-level choices to the engineers, who record them in the code and in section 12. It is not a broad A2A platform: ADR-0006 section 1a lists what is out.

## 1. Scope in one paragraph

The gateway serves a standard **A2A v1.0 JSON-RPC** interface, one endpoint per **participant**. A participant is a managed session (bound to one exact session id) or an externally managed service (a stable id the owner enrols). Any authenticated, enrolled principal can message any current participant. A task carries a clarification (`INPUT_REQUIRED`) and an explicit result; the sender polls with `GetTask`/`ListTasks`, and is also **woken** through its normal readiness gates so a response is never stuck in the database. Out of scope: the OpenRig bridge (ADR-0007), the discovery tool (ADR-0008), streaming, push notifications, public internet, a NAT connector, worker dispatch, Pi/OpenCode, a marketplace, cancellation of working tasks.

## 2. Hard rules (decided; do not change without the user)

1. Reduced scope above. No new operations "for completeness"; the refusals in section 6 are required.
2. **Exact session binding.** A managed-session endpoint is its session id. A replacement is a different participant; open tasks end `FAILED` "session ended"; nothing is redirected. A friendly alias that matches more than one live session is **refused** with the exact candidates.
3. **Contact is open to the enrolled; everything else is not.** Authenticated sessions (via their paired host) and enrolled external principals may send to every current participant, with **no per-destination grants**. Anonymous senders are refused. A principal may **not** read tasks it is not party to, control terminals, answer prompts, spawn workers or edit cards. The public card read is not authority.
4. **Origin is written by the gateway** from the authenticated principal. A `from` field in any body is ignored. Delivered text carries a gateway-written origin line.
5. **Task state is evidence-grounded.** `COMPLETED`, `FAILED`, `REJECTED` and `INPUT_REQUIRED` come only from an explicit report or a system event. A turn ending (`Stop`) is never completion. Delivery receipts (`host_stored`, `pasted`, `accepted`) stay separate and are not task state.
6. **Offline target fails immediately.** No task is created, nothing is queued, nothing is replayed. An uncertain dispatch is recorded as uncertain and never retried.
7. **`CancelTask` exists; a working task returns `TaskNotCancelableError`.** No `CANCELED` state is produced, no interrupt, no "cancel requested" flag.
8. **Uncertainty is not a `TaskState`.** A participant disappearing mid-task is recorded as separate observation metadata (section 7); the task is not finalised on a disconnect.
9. **Retention.** Tasks and results are kept until the **owner** deletes them. No expiry, no purge, nothing copied from the local 30-day cleanup. Records survive a participant restart.
10. **Transport.** LAN and tailnet only, owner-configured destination URLs. Reuse the card poller's dial rules (IP literal, dial-time deny list, no redirects, no proxy, size and time caps). Plain HTTP only inside Tailscale or loopback; LAN needs pinned HTTPS or the existing explicit opt-in. No public destinations, no NAT connector, no new tailnet HTTPS. Say plainly in the docs that A2A asks for HTTPS in production and that tailnet HTTP is a documented deviation.
11. **No live-state mutation.** The migration is additive, runs only at `rtk gateway --listen` with the existing backup, and has not been run. Wire protocol 2 stays 2 unless a change is unavoidable; if so, say so before building it.
12. **Do not claim conformance** until the user has run it. Docs show "current" against "proposed".
13. Keep Network, Graph, SSH entry, host cards, `card.yaml`, the 5 s full-body polling and the open prompt-box issue untouched. No unrelated refactor.

## 4. Where things live

- `internal/a2a/` (new): types (or SDK adapters), the JSON-RPC handler, the task service, the `taskstore` over SQLite, principal and origin types, the outbound client to external services, and an **executor-free** state machine (transitions are applied by reports and system events).
- `internal/gateway/`: chi routes mounted next to the existing ones, auth middleware, `migrations/0003_a2a.sql` (and the migrator entry), admin commands.
- Routes: `POST /a2a/agents/{id}` (JSON-RPC), `GET /a2a/agents/{id}/.well-known/agent-card.json` (public, read-only). `{id}` is a session id or a participant id. The prefix and path are our choice; the card's `supportedInterfaces[0].url` is the POST URL.
- `internal/daemon/`, `internal/server/` (MCP): new session-facing tools and the notification path (section 8). Keep `ratatoskr_send` and the old route working.
- `integrations/a2a-reference/` (new, **its own `go.mod`**, imports nothing from `internal/`): the reference adapter (section 9). This is what proves the contract is usable by outsiders.

## 5. Identity, enrolment, authorization

- **Principals.** `session` (host, session id; authenticated by the host credential, with the daemon naming the acting session; the gateway checks it is a **current** session of that host, as `CurrentSession` does today) and `participant` (an external service; authenticated by its own bearer credential). The gateway derives the principal from the credential, never from a body.
- **Enrolment (owner-authorised, no self-enrolment).** Admin commands on the gateway host, names are defaults: `rtk gateway participant enrol NAME`, `participant register NAME --url URL [--fingerprint sha256:...]`, `participant list`, `participant revoke NAME`, `participant delete-tasks (--task ID | --all-final | --participant NAME)`. The credential is printed once and stored as a hash. Revoking rejects the next call, disables the endpoint, and ends open tasks with a reason. `register` fetches the service's card from its well-known URL under the transport rules, validates it strictly, and stores it. Enrolment can be a different principal from the registered destination URL (a pure ingress client has no URL).
- **Authorization.** Authenticated and not revoked is sufficient to send. Task visibility: `GetTask`, `ListTasks` and `CancelTask` return only tasks where the caller is the **owner** (the creating principal) or the **target participant**; anything else is `TaskNotFoundError`, with no distinction between "missing" and "not yours". `ListTasks` must be caller-scoped and cursor-paginated (spec 3.1.4).
- **Honest limit to state in the docs:** same-user processes on the gateway or a daemon host can read credentials; an enrolled service can message every session, each of which is a model that text can persuade; revocation is the control.

## 6. The A2A surface (all verified against the v1.0.0 sources)

| Method | First delivery |
| --- | --- |
| `SendMessage` | Implemented. New task, or continue a task (`taskId`) the caller is party to. Direct reply (a `Message` result) is allowed where no task is needed. |
| `GetTask`, `ListTasks` | Implemented, caller/party scoped, `ListTasks` paginated. |
| `CancelTask` | Implemented as the refusal: working task gives `TaskNotCancelableError` (-32002); unknown or foreign task gives `TaskNotFoundError` (-32001). |
| `SendStreamingMessage`, `SubscribeToTask` | `UnsupportedOperationError` (-32004); `capabilities.streaming` false. |
| Push notification config operations | `PushNotificationNotSupportedError` (-32003); `capabilities.pushNotifications` false. |
| `GetExtendedAgentCard` | `UnsupportedOperationError`; `capabilities.extendedAgentCard` false. |

Also required: the `A2A-Version` header must be `1.0` (Major.Minor; an empty value is **refused** because this server speaks only 1.0, and the choice is documented) else `VersionNotSupportedError` (-32009); `ContentTypeNotSupportedError` for unsupported modes (text only); unknown methods -32601; bad params -32602; parse errors -32700. Unauthenticated requests get HTTP 401 with `WWW-Authenticate`, forbidden ones 403, before JSON-RPC. The card declares only what is true: `capabilities` all false, one `JSONRPC` interface with `protocolVersion` "1.0", a bearer `securityScheme`, text modes. IDs are separate: `taskId`, `contextId`, `messageId` are A2A ids; session and participant ids are Ratatoskr's; none is derived from another.

## 7. Task state and observations

| State | Set by |
| --- | --- |
| `SUBMITTED` | The gateway, when it accepted the request and dispatched it. Not "the model read it". |
| `WORKING` | Managed target: the harness accepted the input (`accepted`), never earlier. External target: the service returned a working task. |
| `INPUT_REQUIRED` | An explicit report (managed) or the service's own task state (external). |
| `COMPLETED`, `FAILED`, `REJECTED` | An explicit report, the service's own state, or a system event (session ended, participant revoked). Never `Stop`, never a closed pane. |
| `CANCELED` | Not produced in the first delivery. |

**Observation metadata** (a separate table, also exposed in `Task.metadata` under a Ratatoskr-namespaced key if the SDK allows; otherwise only in the gateway's records): `delivery` (`stored`, `pasted`, `accepted`, `uncertain`), `participant_connection` (`connected`, `lost at T`), `reconciled` (bool, by whom). A lost connection sets an observation, **not** a state. It is reconciled by an explicit report after reconnect or by an owner action. A managed session that ends is a system event and does finalise its tasks (`FAILED`, "session ended").

## 8. Getting a response back to the model

This is the part the user called out: an asynchronous answer must reach the model, not sit in a table.

- **Sender side.** New MCP tools for managed sessions (names are defaults): `ratatoskr_task_send(to, body, task_id?)` returns a task reference promptly; `ratatoskr_task_get(task_id)`; the existing `ratatoskr_send` keeps its legacy meaning. The recommended pattern is prompt return plus polling (an engineering recommendation, not a user decision).
- **Target side.** `ratatoskr_task_report(task_id, state, message, artifact?)` lets the target say `input_required`, `completed` or `failed` with text and an optional result. For a target that is a managed session, an incoming task is delivered as a labelled prompt ("from codex@ubuntu, verified by the gateway, task T1") through the **existing** gated paste.
- **Wake.** When a task owned by a managed session changes to `INPUT_REQUIRED` or a final state, the gateway sends a task-event frame to the owner's daemon, which delivers a short notification ("Task T1 needs input: ... / Task T1 completed: use ratatoskr_task_get") through the same readiness gates as messages (held while busy or at a prompt, visible in the log). This reuses the message-delivery machinery; do not build a second one. If the owner is offline the event is recorded and shown on the next `GetTask`; it is not replayed as a prompt.
- **Wire.** Extend the daemon stream with additive frames (task dispatch to a target, task event to an owner). Prefer additive frames that older daemons ignore; **if protocol 2 must change, stop and tell the architect.**
- **External targets.** The gateway is an A2A **client** to the registered URL: `SendMessage`, then mirrors the remote task by polling the service's `GetTask` while it is non-terminal (interval and cap are engineering choices, bounded, no overlap, dial rules apply). A remote `INPUT_REQUIRED` is mirrored, and the sender's answer is a `SendMessage` with the task id that the gateway forwards with the remote task id. No custom stream is demanded of a standard service.

## 9. The reference adapter

`integrations/a2a-reference/`: a small standalone Go program (own `go.mod`, depends on the SDK only, no `internal/` import) that is a **real** A2A server: it serves its own validated card, the four operations and the standard refusals, and does real, model-free work. Suggested behaviour (a documented choice): it receives text, and if the message has no `format: json` or `format: text` line it replies `INPUT_REQUIRED` asking which, then returns line, word and character counts in that format as an artifact. It lets the user run the clarification and result flow without a second model. It is **not** an OpenRig bridge. The monkey may draft it under the supervised workflow; a senior reviews it.

## 11. Acceptance, for the user to run later (written into scenario 6)

1. **First round trip:** a managed Claude on the Mac asks a managed Codex on a remote host to review something; Codex asks one clarification; Claude answers; Codex reports a result; Claude sees the task `COMPLETED` through `GetTask` and was woken on the way.
2. **Auth and forgery:** no credential gets 401; a revoked credential is rejected; a body `from` is ignored and the origin shown is the authenticated principal; a session that is not current for its host is refused.
3. **Scoping:** a third principal gets `TaskNotFound` for someone else's task, and its `ListTasks` omits it.
4. **Session end:** ending the target mid-task marks it `FAILED` "session ended"; a reply is refused, not redirected; an ambiguous alias is refused with candidates.
5. **External service:** enrol and register the reference adapter; the gateway fetches and validates its card; a managed session messages it, answers its clarification and gets its result; stopping the adapter mid-task leaves the task non-final with an observation, and a later send fails immediately.
6. **Failure and refusals:** `CancelTask` on a working task gives `TaskNotCancelableError`; `SendStreamingMessage` gives `UnsupportedOperationError`; a wrong `A2A-Version` gives `VersionNotSupportedError`; an unreachable external URL is refused at registration.
7. **Retention:** tasks remain after a gateway restart and a participant restart; only the owner's delete command removes them.

## 12. Decisions recorded by engineers (fill in, do not erase)

- SDK gate outcome and rationale (backend, 2026-11-08, static only): **adopt the handler** (`a2asrv.NewJSONRPCHandler` with our own `taskstore.Store` and a submit-and-return executor). The five checks pass: the method literals are the spec's PascalCase names, the error table is the spec's, an unsupported or empty `A2A-Version` is refused, `a2a` plus `a2asrv` bring in no grpc, protobuf or genproto, and the store's version tracking is optional. The handler gives us the envelope, parameter checks, error mapping and version check that we would otherwise rewrite; what we keep for ourselves is everything that makes this contract different: principals, scoping, task state from reports, observations. Residual risks, to be checked when P1 type-checks and later when the user runs it: (a) the SDK writes to the store while an execution is open, so our out-of-band writes must wait until the executor has returned, which "submit and return" gives; (b) the version check refuses an empty header only because empty is read as "0.3", so keep our own explicit empty-header rule in front of it; (c) the handler is a plain `http.Handler`, so 401/403 and the `{id}` routing stay in our middleware. The reference adapter (P5) can sit on the SDK server: its literals are right, and its clarification flow is the SDK's native executor model.
- Method-literal and error-code verification result (module `github.com/a2aproject/a2a-go/v2@v2.8.0`, read from the module cache, nothing executed): `internal/jsonrpc/jsonrpc.go:41-51` has `SendMessage`, `SendStreamingMessage`, `GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`, the four push-config methods and `GetExtendedAgentCard`: PascalCase, not slash-style. `:72-86` maps -32700, -32600, -32601, -32602, -32603, -32000 and -32001 to -32009 to `a2a.ErrParseError ... a2a.ErrVersionNotSupported`, exactly the 5.4 table; `ToJSONRPCError` (`:165-215`) puts the code, an `ErrorInfo` reason and metadata in `error.data`. `a2asrv/jsonrpc.go:54` sets `callCtx.ProtocolVersion = a2a.Version` ("1.0", `a2a/core.go:33`); `a2asrv/intercepted_handler.go:282-298` compares Major.Minor and an empty header counts as "0.3", so it is refused with `ErrVersionNotSupported`. ## 14. Outbound authentication and ListTasks (correction, 2026-11-08; supersedes ruling 2 in section 12)

**Why.** The brief says the target must be able to tell the gateway from an arbitrary caller on its network, and A2A agrees: servers "MUST reject requests with invalid or missing authentication credentials" (3.3.2) and "MUST authenticate every incoming request" (7.4), and a client "MUST authenticate the request using one of the schemes declared" in the card (3.1.11, 7.3). A candidate that sends nothing is missing identity-chain functionality, not merely documentation. This is authentication of the gateway, not a per-destination grant: the contact-all policy for admitted principals is unchanged. No new product question is needed.

**What to build (minimal, local, no PKI, no new TLS mode):**
1. **A per-registration outbound bearer secret.** `participant register NAME --url URL` generates it (CSPRNG, at least 256 bits), prints it **once**, and sends it as `Authorization: Bearer <secret>` on every gateway-originated call to that registration's URL (`SendMessage`, the mirror's `GetTask`, answer forwarding). It is distinct from the enrolment credential (inbound) and from the host pairing credential, and neither is ever reused outbound. Re-running `register` rotates it (prints a new one; the old one stops working). The unauthenticated public card fetch at registration carries no credential.
2. **Standard declaration.** The service's card must declare the scheme the standard way: `securitySchemes` with an HTTP auth scheme `{"<name>": {"httpAuthSecurityScheme": {"scheme": "Bearer"}}}` and `securityRequirements: [{"schemes": {"<name>": {}}}]` (the SDK marshals an empty scope list as `{}`, the canonical protojson form; it also reads `{"list":[]}` and `[]`) (proto v1.0.0: `SecurityScheme` oneof member `http_auth_security_scheme`, `HTTPAuthSecurityScheme.scheme` required, `SecurityRequirement.schemes` is a map to `StringList`; the spec has no HTTP-bearer card example, so use the SDK's `a2a` types to marshal and let the lead verify the produced JSON against the proto names). Registration **refuses** a card that declares no HTTP Bearer scheme, or that requires a scheme the gateway cannot satisfy (OAuth2, OpenID Connect, mutual TLS, API key).
3. **Explicit no-auth demo mode.** `register ... --no-auth` accepts a card that declares no security. It prints a prominent warning, stores `auth=none`, shows `NONE` in `participant list`, sends no credential, and the docs call it a demo, **not** the authenticated path. Without the flag, an unauthenticated card is refused.
4. **Storage and projection.** Keep the secret in the gateway database column of `a2a_participants` (migration 0003 has never run, so amend it in place), selected only by the outbound-client factory. Explicit column lists everywhere else. The database stays mode 0600 and its `VACUUM INTO` backup inherits that. The secret must never appear in `participant list`, `--json` output, task or message metadata, observations, events, the ledger, logs, error strings, the Graph, any card, or the JSON of any API. Strip the `Authorization` header from any error that wraps a request. The client is built per registration, bound to that one URL, no redirects (as now), so the secret cannot go anywhere else. Tests (written, not run) must prove the secret is absent from list output, from a failing request's error text and from the log.
5. **Plain HTTP.** A LAN `--insecure-http` registration sends the secret and the task in the clear on that network: `register` says so. Loopback and the tailnet need no flag (the tailnet is encrypted by Tailscale). No new TLS mode.
6. **Origin trust binding.** The gateway keeps writing `ratatoskr.origin` metadata. The service may rely on it only because the request authenticated as this registration's gateway; the docs say precisely that, and that it proves the gateway's word, not the original sender's identity beyond the gateway's own checks.
7. **The reference adapter validates it.** It requires `Authorization: Bearer <token>` equal to its configured secret (constant-time comparison) and otherwise answers **401 with `WWW-Authenticate: Bearer`** before any JSON-RPC. The token comes from `--gateway-token-file PATH` or the environment variable `A2A_GATEWAY_TOKEN`, never from argv. Its public card declares the Bearer scheme and requirement as in item 2. It **refuses to start without a token unless `--no-auth` is given explicitly**, and `--no-auth` prints a demo banner. The README's first lines and scenario 6 present the authenticated path as the completed one.
8. **Secret entry for the adapter.** The owner copies the one-time secret from `register`'s output into the adapter's token file. Ordering note for the docs and the scenario: start the adapter with a placeholder token file, `enrol`, then `register` prints the secret; paste it into the token file. **The adapter re-reads the file on every request, so no restart is needed.** Alternatively register first against an adapter started in `--no-auth`, then re-register after switching it to authenticated; engineers pick the cleaner flow and document it. The adapter must serve its card even before the right secret is configured.

**ListTasks.** The spec defines `totalSize` as "Total number of tasks available (before pagination)" (3.1.4, proto field 4, required), and its examples count all matches, not the page. The candidate returns the page count, which is wrong. Fix it: return the number of tasks visible to the caller that match the filter, before pagination (a `COUNT` over the same caller-scoped query). `pageSize`, `nextPageToken` (always present, empty on the last page) and the status-timestamp descending order (MUST) must also hold; check the sort. Do not omit `totalSize`: the field is required.

**Rules that do not change:** contact-all for admitted principals, no per-destination grants, `CancelTask` refusal, observations not states, retention until owner deletion, LAN/tailnet only, no public exposure, no PKI platform, no secrets in logs or docs. GR-3 applies; no commit or push.
