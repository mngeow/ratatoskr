# Input and shutdown bug candidate

Supervisor engineering.frontend; parent qitem-20261104145908-5cf49d9699fb48f8. User reported mouse focus unavailable and Ctrl+C not exiting rtk. GR-3 unchanged: all implementation/static reasoning is UNTESTED; no execution permission follows from the user's run.

Initial design/monkey brief below is historical. Final candidate at the end is current. Follow-up qitem-20261104151413-2b18cba0d8af038a confirmed the full-UI freeze and decided Ctrl+C; it was incorporated without restarting.

## Senior design

Confirmed source findings: current SendKey/Paste hold emuMu through PTY completion; pipe drain performs PTY writes directly and permanently closes on timeout. Query replies inside emu.Write and in-band resize can block under emuMu. Snapshot and synchronous UI Resize can therefore delay View/Update. Current shutdown signals direct child only. Exact before/after source references will be recorded after refinement.

Root refinement after monkey first version: keep pipe drain independent of PTY writer. Drain copies into bounded transport queue without waiting for PTY; input batches have completion fences. Wait for actual PTY completion OUTSIDE emuMu, while inputMu still preserves key/paste/Enter ordering. Bounded saturation must return visible backpressure, never permanently kill input merely because child is slow. Router PasteSubmit remains direct, ctx-cancellable, byte-counted and serialized; fence prior queued input before it. A slow child can still stall its own input worker until it reads or shutdown cancels, but cannot block UI. Snapshot reads an atomic cached frame only; x/vt Write/Render run exclusively on the emulator worker. UI resize uses coalesced nonblocking RequestResize, not synchronous Resize.

Shutdown: record child-owned process group (Getpgid(pid)==pid) after pty.StartWithSize creates its session. Group signal only while child is unreaped, under the same lifecycle lock as reaping. Because cmd.Wait currently reaps outside that lock, senior will replace the wait path with bounded-interval Wait4(WNOHANG) under lifeMu, then Process.Release (all cmd streams are PTY files; no exec copy goroutines), to avoid signalling a reused PID/group. SIGTERM then force-kill verified owned group; if ownership fails, only owned direct child. Wrapper exiting before escalation and tools in other groups remain limitations. Timeout errors wrap context.DeadlineExceeded. No new launch API.

### Findings and source map

- **3d confirmed:** before-fix SendKey/Paste held emuMu through completion; replyLoop waited for PTY writes and killed input after timeout; query parsing/Resize and Snapshot reached the same lock. Before-fix references captured in frontend tool output: pane.go:309, :348, :457–460, :484–487, :392–395, :418–419, :540–543. Per-chunk timeout was not a proof against freezing.
- **Empty-write cycle latent, trigger unproven:** the old zero-read acknowledgement could wait while flushInput attempted another empty write. However, fallbackKey normalization and its Ctrl+C Text/lock/repeat test predated the user's reported build. Accepted normalized Code/Mod paths appear nonempty by source; actual decoder/binary behavior was not observed. We did not inspect/recreate the missing owner binary.
- **Fd/deadline concern refuted:** Go os/file_unix.go retains NewFile's already-nonblocking descriptor without the flag that makes Fd restore blocking. pollerMaster uses that path. No extra Fd workaround added.
- **Current UI surface:** pane.go:377 Snapshot and :482 Err read atomics only; mouse.go:109 MouseEnabled and :201 InputReady use atomic/status reads. resize.go:17 RequestResize only validates/records/coalesces. No pane mutex or x/vt/child I/O is entered by View/Update.
- **Current emulator/transport:** emulator.go:19 owns all Write/Render/encoding/resize. Callers have a three-second operation bound; emulator timeout latches unavailable and leaves the last good frame. transport.go:97 drains independently into 512 slots/2MiB; :127 writes PTY independently. Overflow is backpressure; deadline does not kill the drain. Real OS failure disables input visibly.
- **No synthetic empty marker:** transport.go:170 counts real writes from pinned x/vt (key/mouse once; nonempty paste once or three in mode 2004). The pipe read buffer fits each supported write. Empty input encoding yields ErrEmptyEncoding, not successful completion; empty query output is ignored. Completion fences follow actual bytes. Late reads retain canceled batch identity.
- **Ordering:** pane.go:425 PasteSubmit fences prior buffered input, then serializes bracketed paste, delay and separate Enter. ESC refusal, context cancellation and cumulative WriteError counts remain. Successful Enter completion precedes UserSubmitted, so router paste cannot overtake it.
- **Router isolation:** model.go:497 startInput sends UserDraft before child bytes and UserSubmitted after successful Enter inside the ordered Cmd. Draft-clear/F4 actions also run there. Update's Snapshot/PendingOnQuit are atomic reads by contract; history.go reads remain in Cmds. interrupt.go:142 marks a stuck Cmd unavailable after three seconds. Bubble Tea tea.go:740–744 explicitly does not join blocked Cmd goroutines on quit.
- **Mouse:** tui/mouse.go:38 reuses paneWidths/screenTop. Focus-only left press/release is consumed; drag/release stays with its press owner, coordinates clamped. Wheel targets the pointer's pane without focus/draft/epoch changes and drops silently on saturation. Disabled/unavailable input enqueues no mouse/draft. vt resetModes routes defaults through callbacks (RIS clears tracking). Ultraviolet decoder.go:1661–1698 retains the pressed button on motion, source evidence only. Legacy coordinates clamp to 222.
- **Ctrl+C:** interrupt.go:93 implements the user-decided rule with injected clock and one-second untested window. First ready-pane press interrupts; second requests quit using draft state before the first. Other keys/focus disarm; expired feedback clears. Nil/exited/failed/stuck/log/too-small requests quit on one press. Ctrl+C/F10 confirms an armed warning; a full queue cannot block that model decision.
- **3f confirmed/refined:** process.go:17 signalOwned and :46 waitLoop share lifeMu for verification/signalling/reaping. Start records pgid==pid after Setsid; every group signal rechecks ownership and only occurs while unreaped. Otherwise only the owned direct child is signalled. Wait4(WNOHANG) preserves normal exit code, maps signal to -1, releases the Go process handle and invokes onExit once. Adds up to 100ms notification latency. Shutdown timeout errors wrap context.DeadlineExceeded.

### Residual risks and limits

All behavior remains untested. Go cannot preempt a parser/renderer/router call that never returns: it is isolated from the UI and exposed by status/watchdog, but its worker/Cmd may remain until rtk exits. Automatic recovery after emulator timeout or real write failure is not implemented. CloseContext can return at its caller deadline before background cleanup completes.

User paste/key text over 1MiB is refused before encoding/PTY bytes; the conservative draft mark remains held until Enter/F4. A large paste to a slow child can hit the three-second whole-operation bound and return a partial-input error. This does not permanently kill the drain; UI can temporarily show its outstanding Cmd unavailable. Separate emulator timeout/OS failure latches unavailable. Query timeout/saturation can drop a response with recorded I/O warning; subsequent child degradation is untested. The 50ms paste/Enter delay, all thresholds, custom bindings, Unicode, real mouse selection and redraw remain unverified.

A wrapper exiting on SIGTERM before escalation may leave a descendant that ignores signals; after reaping, that group is not assumed safe to signal. Master-close HUP may reach it; tools in other groups are not reached. No unrelated group is signalled. Native text selection while capturing mouse needs terminal-dependent Shift/Option bypass. Double Ctrl+C intentionally no longer exits only one harness.
