## Child terminal environment

Source-derived choice sent to backend: TERM=xterm-256color, COLORTERM=truecolor. x/vt's palette and RGB SGR support motivate those values; this does not promise every xterm feature. Child keyboard remains legacy. Remove COLUMNS/LINES (PTY winsize is authoritative), TERM_PROGRAM, TERM_PROGRAM_VERSION, TERM_SESSION_ID, VTE_VERSION, WINDOWID, WT_SESSION and ITERM_/KITTY_/WEZTERM_ vendor hints. Backend owns childTerminalEnv and rig identity/TMUX removal. Do not pass the outer terminal's identity through to the inner harness.

## Senior refinement in progress

Paste errors retain cumulative byte count through cancellation during delay/Enter and expose BytesWritten() bool plus ByteCount() int. The PTY transaction lock spans paste, delay and Enter, excluding query replies too. User/query writes have a provisional two-second transport bound; a failure closes the emulator input drain rather than permanently blocking UI. Scrollback is bounded at one line because x/vt's zero setter is a no-op. Cell allocations are bounded independently of winsize's uint16 range. Tests are authored in internal/pane/pane_test.go but unrun; they cannot establish the poller or actual harness behavior.

User key/paste completion uses a zero-length io.Pipe write as a barrier after encoding; the reply loop acknowledges it only after prior PTY writes finish. Go io/pipe.go write loops at least once even for empty input. This assumes pinned x/vt supported-key encodings and query replies are nonempty; empty user paste returns without entering x/vt. This synchronization is untested and has a dedicated unrun pipe-based test. UI input is ordered per pane, bounded to 128 pending actions, and processed off the UI update thread. Draft epochs keep queued or rejected later input held after Enter. UserSubmitted resets budget only; UserDraft is the separate FIFO gate signal agreed with lead/backend.
